name: shark-intake
description: "Managing Partner intake: get the venture, stage and sector; pick the relevant sharks (not all 100); run the panel and, if asked, the fundraise roadmap. Use at the start."
---

1. Get: venture, one-line idea, stage (pre-seed/seed/A), sector, geography, current traction (real numbers), and the ask if any.
2. Select sharks: the investor types/sectors/stages that actually fit (e.g. seed: angels, networks, micro-VCs, seed VCs, relevant sector funds, non-dilutive) + a few skeptics and a stretch type for blind spots. Usually 12-25, not all ~100 (cost + relevance) unless asked for the full panel.
3. Spawn the chosen sharks (light model); give each the idea + strategy (+ deck/numbers if provided). They use `investor-verdict`.
4. Collect verdicts, run `panel-verdict-synthesis`, report to the CEO. If the founder wants to raise, also run `fundraise-roadmap`. Write `raise/<venture>/PLAN.md`; add a row to `raise/STATUS.md`.

> Guardrails (read every time): these sharks are ARCHETYPES grounded in documented investor criteria — NOT real named investors. Their verdicts are simulated stress-tests to sharpen the pitch, NEVER real investment interest, offers, or commitments; never imply any real investor said or will do anything. All check sizes, valuations, schemes, instruments and tax points are from 2024-2026 sources that change — cite, date, and re-verify; securities law, valuation, FEMA/SEBI, tax and instrument choice go to a CA / CS / startup lawyer. This team PREPARES the raise; it never issues securities, files, quotes terms, or contacts real investors without Saket's approval (that is investor-relations-lead's job, with approval). No fabricated traction or metrics — the roadmap runs on real numbers only.
