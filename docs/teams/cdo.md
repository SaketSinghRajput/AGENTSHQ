## Skills

| Skill | Description |
|---|---|
| `ai-adoption` | Internal AI adoption: approved tools, data-handling rules for AI tools, prompt/skill libraries, agent workflows (like AgentHQ), training, time-saved tracking. Use for AI enablement. |
| `ai-evaluation` | AI evaluation: golden datasets, task metrics, LLM-as-judge with human calibration, safety/robustness tests, regression gates. Use to evaluate AI. |
| `ai-strategy` | Data & AI strategy: use-case discovery, value × feasibility scoring, build/buy/partner, roadmap, capability building. Use for AI planning. |
| `analytics-engineering` | Analytics engineering: layered models (staging → marts), tests, documentation, metric definitions. Use for data modelling. |
| `applied-ai` | Applied AI delivery: problem framing, data readiness, PoC, provider choice (Claude API, Ollama local models), cost/latency, integration plan with CTO. Use for AI use cases. |
| `business-intelligence-dashboards` | BI dashboards: requirements, KPI definitions, visual design, self-serve, insight write-ups. Use for dashboards. |
| `cdo-intake` | Chief Data & AI Officer procedure to classify a request into a scenario, gather facts, staff the team and create the plan. Use at the start of every data and AI task. |
| `cdo-status-report` | Chief Data & AI Officer status report for the founder. Use when asked for data and AI status or at end of session. |
| `cdo` | Chief Data & AI Officer mode - runs data and AI across the company: data platform, BI, data governance, AI strategy, responsible AI and AI adoption with 10 specialists. Invoke with /cdo. |
| `data-governance` | Data governance: catalog, owners/stewards, classification (public/internal/confidential/personal), access model, quality SLAs, retention, DPDP alignment with GC privacy counsel. Use for governance. |
| `data-platform` | Data platform architecture: sources, ingestion (batch/stream, IoT/MQTT), storage, modelling layers, orchestration, cost, security. Use for data infra. |
| `data-science` | Data science: forecasting, classification, segmentation, causal inference, backtesting, uncertainty communication. Use for analytical models. |
| `responsible-ai` | Responsible AI: AI use policy, impact/risk assessments, bias and fairness tests, transparency and labelling, human-in-the-loop, incident process; coordinate with GC AI counsel. Use for AI governance. |
